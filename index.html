What it is

CreateLee holds three copies of the same eight Signoff export filenames — QA reviews, audit events, approvals, escalations, role spec, AI inventory, training records, and incident notifications. They are not equivalent: one copy is the golden acceptance target, one is a "not acceptable" rehearsal library, and one is failed model output. The point is to rehearse the shape of the evidence path, not to fake the substance.

What you get

Eight export shapes

The exact CSV columns Signoff's validator expects, so the gate can be format-checked before a client exports anything.

Validator

A script that reads the export shapes and reports PASS / PASS_WITH_FINDINGS / FAIL per file.

Golden examples

An ACCEPTABLE reference set to point every future run at — the target to beat.

Honest warnings

The rehearsal-library copy fails 4 of 8 against the validator; it is labelled, not hidden.

How it fits the Helix ecosystem

CreateLee is part of the Helix Codex / Helix Prime body of work — same author, same philosophy (offline, explainable, auditable, no generative model in the evidence path). It is an independent repository with no shared codebase or runtime with Helix Prime, live-support-assistant, or CompliProof: portfolio membership, not technical integration. It feeds the Signoff gate: the validator reads these shapes and produces the pack verdicts that Helix-Codex's production gates consume as content only — the signature itself is an external, owner-supplied act.

Honest boundary

This is rehearsal data with unverified provenance, not production use. Every row is tagged simulated; it closes no production gate and authenticates nothing. Do not infer that bundled material is synthetic, anonymized, or free of personal data — it is not production-proven, and the operational rows must be replaced with genuine system exports before any real signoff. No external security audit or certified data isolation is claimed.
