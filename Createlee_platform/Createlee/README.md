# Createlee / Engeznee

A small, dependable local document generator for a **telecommunications call-centre operations** team. It turns two canonical CSV schemas plus your own data files into QA, WFM, incident, training, AI-inventory, SOP and knowledge-base documents in **CSV / TXT / JSON / PDF / DOCX**, with **ISO-8601 UTC timestamps** on every generated file.

No framework bloat, no database, no build step. One Flask process, plain HTML/CSS/JS.

## The two canonical CSVs

Everything the platform generates is defined by these two files. **Edit the CSVs, not the code**, to add a document type, a criterion, a field or a format.

### `questions.csv` — criteria / questions / sections

| column | meaning |
|---|---|
| `question_id` | unique ID, e.g. `Q-QA-001` |
| `domain` | `QA` \| `WFM` \| `INCIDENT` \| `TRAINING` \| `AI_INVENTORY` \| `SOP` \| `KNOWLEDGE_BASE` |
| `document_type` | e.g. `qa_scorecard`. Any new value creates a new document type automatically. |
| `section` | heading in the output document (order of first appearance is preserved) |
| `prompt` | the criterion / question text |
| `answer_type` | `yes_no` \| `text` \| `number` \| `score_1_5` \| `choice` \| `date_iso8601` \| `percent` |
| `required` | `true`/`false` |
| `weight` | numeric scoring weight |
| `options` | `\|`-separated choices |
| `default_value` | pre-filled answer; empty becomes `— (to be completed at review)` |
| `tags` | `;`-separated labels |

### `mapping-table.template.csv` — field mapping

| column | meaning |
|---|---|
| `mapping_id` | unique ID, e.g. `M-QA-001` |
| `domain`, `document_type` | must match `questions.csv` |
| `source_file` | filename of an uploaded data CSV, e.g. `calls.csv` |
| `source_field` | column in that file |
| `target_field` | column heading in the generated document |
| `data_type` | `string` \| `integer` \| `decimal` \| `boolean` \| `timestamp` \| `date` |
| `transform` | `none` \| `upper` \| `lower` \| `title` \| `trim` \| `iso8601` \| `integer` \| `decimal2` |
| `format` | `iso8601` for timestamp columns |
| `required`, `default_value`, `validation`, `notes` | as labelled |

Bundled sample data: `calls.csv`, `agents.csv`, `incidents.csv`, `ai_systems.csv`, `kb_articles.csv`. Uploading a file with the same name replaces the bundled copy.

The bundled schemas define **9 document types** across 7 domains (82 criteria, 62 field mappings).

### Alternative: a plain checklist `questions.csv` (auto-detected)

You do **not** have to use the 11-column schema. A simple audit checklist is accepted verbatim:

```csv
Ref,Question,Yes,Partly,No
W-01,Are AI-proposed QA actions reviewed by a named human before acceptance?,,,
W-02,Is there a kill switch and are AI agent accesses revocable on request?,,,
...
```

Detection rule: a `Question` column present and no `prompt` column => **checklist mode**. Createlee then:

- treats `Ref` as `question_id` and `Question` as the criterion;
- treats `Yes` / `Partly` / `No` (also `N/A`, `Pass`, `Fail`, `Partial`, …) as response columns;
- defaults to domain `AI_INVENTORY`, document type `ai_governance_checklist`, section `AI Oversight Checklist Items`;
- produces a **fillable checklist** with `[  ]` boxes, `Evidence / Notes` and `Owner` columns, plus a completion-summary section;
- writes the same rows into the CSV/JSON output so it can be filled in and re-uploaded.

Optional extra columns (any order, header names case/space/underscore tolerant):
`Domain`, `Document_Type`, `Section`, `Weight`, `Owner`, `Evidence`, `Notes`, `Category`, `Tags`.
Use `Section` to split the checklist into control families. See
`samples/optional/questions-ai-governance-checklist-extended.csv`.

`mapping-table.template.csv` is also tolerant: only **`source_field` + `target_field`** are required;
all other columns are optional, and an empty / `ALL` / `*` `domain` or `document_type` acts as a
wildcard. See `samples/optional/mapping-table.checklist-example.csv`. If no mapping row matches a
checklist document type, the checklist table is built automatically — no extra file needed.

> Document types are driven by `questions.csv`. Mapping rows left over from a previous schema are
> still listed by `list` (flagged *mapping-only*) but are not generated by default.

## Workflow — human approval is mandatory

```
upload (multiple docs)  ->  analyze  ->  generate  ->  STAGED DRAFTS
                                                        |
                                          you open every preview
                                                        |
                            tick "I have reviewed..." + choose Save / Email / Both
                                                        |
                                          APPROVE & EXECUTE
                                                        |
                              files written to outputs/ + optional email
```

**Nothing is written to `outputs/` and nothing is emailed before you press *Approve & Execute*.** Each approval is appended to `outputs/createlee_approval_log.jsonl` with an ISO-8601 UTC timestamp, session, document IDs, file list and recipient.

### Engeznee commands

| command | effect |
|---|---|
| `help` | full command list |
| `analyze` | rows, columns, detected formats (ISO-8601, E.164, integer, decimal, boolean, %), and numeric stats (N / sum / mean / min / max) |
| `list` | every document type defined by your CSVs |
| `status` | Ollama / cloud / email / web integration status |
| `web: <query>` | attach live public-web references (URL + ISO-8601 retrieval time) |
| `generate all` | stage all 9 document types |
| `generate QA, WFM as pdf,csv,json` | selected domains + formats |
| `generate qa_scorecard as json` | one specific document type |
| `generate incident_report as pdf web` | add live references |
| `generate all no timestamp` | omit the ISO-8601 stamp from filenames |
| `preview` / `clear` | show / discard staged drafts |
| `save` / `email to name@company.com` | pre-fills the approval panel |
| `evidence` | build the 8-file Signoff evidence pack + validation report |
| `evidence --as-of 2026-11-06` | re-measure the 90-day window ending on that date |
| `evidence --as-of 2026-11-06 validate only` | validate **your real** exports read-only (your 8 CSVs are never overwritten; only the derived report is refreshed) |
| `library` | build the reusable system-file library + validation report |
| `library --as-of 2026-11-06` | re-measure the library against a specific as-of date |
| `handoff` | build one ready-to-send folder per production-NOT-ready project |
| `handoff --as-of 2026-11-06` | re-measure the hand-off packs against a specific as-of date |

Formats: `csv`, `txt`, `json`, `pdf`, `docx`.

## Signoff evidence pack (the 8-file operational export task)

`evidence.py` is a self-contained module + CLI, exposed in the app as the
`evidence` chat command and the `POST /api/evidence` route. It writes 8 CSVs with
the exact Section-2 filenames and required columns, then validates them **without
ever deleting or rewriting a row**.

| # | file | required columns | proves |
|---|---|---|---|
| 1 | `qa_review*.csv` | `ts, ai_action, human_action, reviewer_id, agent_id` | every AI-proposed QA action reviewed by a named human |
| 2 | `*audit*.csv` | `ts, actor, event_type` | kill switch / access revocation / access review / retention / PII log checks |
| 3 | `*approval*.csv` | `ts, gate, decision, approver_id` | AI-proposed decisions named by approver |
| 4 | `*escalation*.csv` | `ts, escalated_by, supervisor_id, authorised` | escalations go only to authorised supervisors |
| 5 | `role*spec*.csv` / `role*export*.csv` | `ts, role, assigned_to, is_authorised_supervisor` | named accountable person + least-privilege roster |
| 6 | `*ai*inventory*.csv` | `ts, row_type, provider_name` | AI provider inventory + signed no-training contract term |
| 7 | `*training*.csv` | `ts, staff_id, module_name, completed` | staff AI-training completed + verified |
| 8 | `*incident*.csv` | `ts, incident_id, notified_within_sla, owner` | incident notifications within SLA with named owner |

Key behaviours:

* **As-of date + 90 days.** `--as-of 2026-11-06` measures the window
  `2026-08-08 .. 2026-11-06`. Older events are still parsed but excluded from
  coverage percentages.
* **Read-only validator.** No row is deleted to "make it look clean". Blank
  reviewers, `authorised=no`, SLA misses, missing contract terms and training not
  completed are all reported as honest findings. Status is `PASS`,
  `PASS_WITH_FINDINGS` or `FAIL`.
* **Column aliases.** `ts` also accepts `timestamp, time, date, created_at,
  date_time, datetime`; `reviewer_id`, `approver_id`, `supervisor_id`,
  `authorised`, `named_accountable`, `completed`, `notified_within_sla` all have
  accepted variants (see the report's "Accepted Column Aliases" section).
* **Excel content saved as `.csv`.** UTF-8 / UTF-8-BOM / UTF-16 / CP1252 /
  Latin-1 encodings and comma / semicolon / tab / pipe delimiters are
  auto-detected. A working demo is written to `examples_excel_as_csv/`.
* **Row-count / event-type expectations.** Empty (header-only) files fail;
  file 2 needs `kill_switch|access_revoked`, `access_review` and
  `retention_check|pii_log_check`; file 5 needs exactly one
  `named_accountable=yes`; file 7 requires lowercase `yes` (not `Completed`).
* **Output.** The pack folder contains the 8 CSVs, the validation report in all
  5 formats (`evidence_validation_report_<ISO8601>.*`), raw
  `evidence_validation_report_data.json`, `INDEX.csv` and `README.txt`.

Standalone CLI:

```bash
python3.11 evidence.py --out /workspace/evidence_pack --as-of 2026-11-06
# validate your OWN real exports without overwriting anything:
python3.11 evidence.py --out /workspace/evidence_pack --as-of 2026-11-06 --validate-only
```

### Two validators — do not confuse them

| Validator | Who it is for | What it does |
|---|---|---|
| **Permissive** (`evidence.validate_all`) | **real** client exports | Accepts aliases, extra columns, blank fields; reports them as honest findings |
| **Strict** (`evidence.validate_strict`) | the **generated** fixtures | Exact header match, lowercase yes/no, no blank owner, per-file control rules. Mirrors `validate_signoff_csv.mjs` |

The generated fixtures must score **0 FAIL** on the strict validator before they
are sent to a client. Every pack writes `VALIDATION_STRICT.json` and
`VALIDATION_STRICT.txt`; the verdict must read `ACCEPTABLE`.

### Per-project hand-off packs (`handoff.py`)

`handoff` builds one folder per production-NOT-ready project — the exact file set
that project needs, in the exact format Signoff accepts:

```
handoff/
├── REQUESTED-FILES-BY-PROJECT.md    the cross-project list
├── CLIENT-INSTRUCTIONS.md           how the client fills the files
├── INDEX.csv / handoff_manifest.json
├── signoff/                         8 evidence CSVs + strict validation
├── helix-codex/                     9 gate-evidence JSON templates + 2 ownership CSVs
├── live-support-assistant/          procedure_corpus(.csv/.json) + labels
└── compliproof/                     system_a + system_b + reconciliation + P0 checklist
```

Each project folder also has `REQUEST_LIST.md`, `CLIENT-INSTRUCTIONS.md` and
`request_manifest.json`. The manifest names, per project, what Createlee **cannot**
generate (certification, external audit, architecture/DR/security/legal review,
hosted CI, TLS, anchor receipts) so those gates stay honestly open.

```bash
python3.11 handoff.py --out handoff --as-of 2026-11-06
```

**Approvals.** No external organisational approval is required to produce these
internal operational exports — they are data dumps your systems already generate.
Createlee's own operator review gate still applies to the *AI-authored
validation report*: it is staged as a draft and is only saved/emailed after you
tick "I have reviewed these documents" and press Approve & Execute. Nothing is
ever emailed automatically.

> **Honesty boundary.** The 8 CSVs shipped with Createlee are **synthetic
> format/coverage fixtures** derived from the bundled sample data. They are NOT
> real compliance evidence. Replace them with genuine exports from your QA / WFM /
> incident / training / AI-inventory systems (then use `--validate-only`) before
> any actual signoff.

## Integrations (all optional, all degrade gracefully)

### Local Ollama
`llm.py` probes `http://127.0.0.1:11434/api/tags` and uses the first downloaded model (or `OLLAMA_MODEL`). Run Createlee **on the machine where Ollama is installed** and it is picked up automatically — no code changes. It is used only for optional prose polishing on SOP / knowledge-base text and for interpreting an unrecognised free-form request. **The LLM never decides platform behaviour**; command parsing is deterministic, so the platform stays stable when no model is reachable.

> In this sandbox VM there is no Ollama binary or endpoint — your Ollama install is on your own machine. Status will read `not reachable here`, and generation still works 100%.

Optional cloud fallback: set `CREATELEE_CLOUD_LLM_URL` / `CREATELEE_CLOUD_LLM_KEY` / `CREATELEE_CLOUD_LLM_MODEL` for any OpenAI-compatible endpoint.

### Email from your personal address
Createlee cannot link to your mailbox without credentials — no tool can. Copy `.env.example` to `.env` and set `CREATELEE_SMTP_*` (e.g. Gmail **app password**). Then `Save & Email` / `Email` sends the approved attachments via SMTP.

**Without credentials** nothing is silently sent: a portable `.eml` draft with all attachments is written to `outputs/`, which you can open and send from your own mail client. Sending is only ever called from the approval endpoint, and only with an explicit `approved: true` flag.

### Live web data — read this carefully
`websearch.py` uses the free, keyless DuckDuckGo Instant Answer API and direct page fetches. Results are attached as **attributed references** with URL, source, snippet and an ISO-8601 retrieval timestamp.

No automated system can honestly guarantee *"100% perfectly matching with the most updated real life data from the web"*: web content is dynamic, sometimes blocked, sometimes wrong, and tariff/regulatory facts are operator-specific. Createlee treats **your uploaded CSVs as the authoritative source**, labels web results as supplementary leads, marks unfilled criteria as `— (to be completed at review)`, and requires your explicit approval. That human gate is the actual accuracy control.

## Output

- Location: `outputs/` (configurable via `CREATELEE_OUTPUT_DIR`).
- Filename: `{domain}_{document_type}_{YYYYMMDDTHHMMSSZ}.{ext}` — ISO-8601 basic UTC by default.
- Inside every file: `generated_at_iso8601`, `time_standard`, `document_id`, `review_status`, source-file list, numeric analysis table, and (when requested) the live reference table.
- PDF footer carries the ISO-8601 standard + page number; DOCX/JSON/TXT/CSV carry the same metadata.

## System library (procedure corpus + labels + reconciliation)

`library.py` builds a **reusable library of system files** to be referred to afterwards.
It is exposed as the `library` chat command, the `POST /api/library` route and a CLI.
Start small and expand later: replace any file with your own export of the same name.

```bash
python3.11 library.py --out /workspace/system_library --as-of 2026-11-06
```

What it produces:

| Output | Columns | Rows |
|---|---|---|
| `procedure_corpus.csv` / `.json` | `doc_id, title, content, tenant_id, published, version, retired` | **24** (required >= 20) |
| `expected_outcome_labels.csv` | `ticket_id, tenant_id, question, expected_decision, expected_sop_id, source` | **64** (required >= 50) |
| `system_a.csv` | `id` (key), `customer_name`, `plan`, `status` | 20 |
| `system_b.csv` | `id` (key) + matching business columns | 19 |
| `reconciliation_report.csv` | `id, in_system_a, in_system_b, *_match, finding` | 21 union keys |
| `uploaded/` | the 6 **real** signoff files you supplied | 4-8 each |
| `evidence/` | the 8 exact-named Signoff CSVs | as previous task |
| `systems/` | 14 compact system files (tenants, agents, AI agents, customers, plans, tickets, SLA, channels, controls, roster, approvals, change log, manifest-referenced exports) | 4-30 each |
| `references.csv`, `INDEX.csv`, `LIBRARY_MANIFEST.json`, `README.txt` | manifests + web references | — |
| `library_build_report_<ISO8601>.*` | build & validation report in all 5 formats | — |

Key behaviours:

* **Real uploaded files.** Your 6 files are OOXML workbooks saved with a `.csv`
  extension. `evidence.read_rows` detects the `PK` zip magic, decodes them
  read-only via openpyxl and writes UTF-8 CSV copies. Every row is preserved.
* **Web grounding.** 12 real published standards (ITU-T E.164/E.156/E.169.1,
  E.800, TM Forum eTOM/SID/TAM, ISO/IEC 42001, EU AI Act, SIM-swap fraud) were
  fetched from the live web; URLs and ISO-8601 retrieval times are recorded in
  `references.csv` and in the report. Procedure text is grounded in them.
* **Simulated, not synthetic-only.** Operational rows are realistic telecom data
  labelled `synthetic` / `real ticket` in the `source` column; the 6 `uploaded/`
  files are your actual records. Web sources are reference material, **not**
  customer data.
* **Reconciliation by key.** `system_a.csv` and `system_b.csv` share `id`. The
  report preserves A-only keys, B-only keys and plan/status/name mismatches as
  honest findings. **No row is deleted to force a match** (`rows_deleted=0`).
* **Gaps preserved.** 4 labels reference a draft or retired procedure; the
  `delivery_manifest.csv` references 3 files that were not supplied (Createlee
  generated simulated versions under `systems/`); `training_records.csv` uses
  `Yes`/`Completed` where Signoff expects lowercase `yes`. All are reported.

**What your files cannot close** (recorded verbatim in the report and README):
tenant isolation, authenticated end-to-end flows, hosted telemetry/escalation
transport, external security audit, billing integration. These need your
organisation's engineering and security teams — no generated CSV can evidence them.

> **Honesty boundary.** Web sources are real public standards used as reference
> grounding, NOT customer data. All operational rows are simulated; replace them
> with genuine exports before any real signoff.

## Settings and the local model

The **⚙ Settings** panel in the web app lists every model Ollama has installed and
lets you pick the one Engeznee uses. The choice is persisted to `settings.json`
(`CREATELEE_SETTINGS_PATH` overrides the location) and applies immediately.

- **Auto-start.** On launch the app probes `OLLAMA_HOST`; if nothing answers and
  `autostart` is on, it runs `ollama serve` detached and waits (in a background
  thread, so the first page load is never blocked). The *Start Ollama* button does
  the same on demand. Set `CREATELEE_AUTOSTART_OLLAMA=0` to disable.
- **Host normalisation.** Ollama's own CLI exports `OLLAMA_HOST` as `host:port`
  with no scheme; `config.py` adds `http://` so Python requests work.
- **Thinking models** (qwen3 and similar) are called with `think: false`. Without
  it they spend the whole token budget on hidden reasoning and can return an
  empty `content` field.
- **Default model.** If you have not chosen one, the app prefers a tool-capable
  family (qwen3, qwen2.5, llama3.x, mistral, …) over an arbitrary first install.

## Engeznee — executive assistant

Anything that is not an explicit command goes to the agent (`agent.py`), not to a
keyword matcher:

- **Conversation** — the last 12 turns are sent with every request, so follow-ups
  ("and for CompliProof?") resolve against what was just said.
- **Reasoning + tools** — a bounded loop (default 6 steps) lets the model observe a
  tool result and decide the next step. Tools: `platform_status`, `list_documents`,
  `analyze_uploads`, `generate_documents`, `build_evidence`, `build_library`,
  `build_handoff`, `project_readiness`, `web_research`, `select_model`,
  `start_ollama`.
- **Grounding** — a live `RUNTIME CONTEXT` block (current model, installed models,
  upload/staged counts, hand-off status, exact per-project gate facts) is injected
  into the system prompt so the assistant cannot invent a model name or mis-state
  a gate.
- **Honest degradation** — with no model reachable it answers from live platform
  state and marks the reply `offline`; it never pretends to have reasoned.
- **Safety** — tools stage drafts and build derived artefacts. None saves or
  emails. The human approval gate is unchanged: an agent can stage, never send.

## Known boundaries

- State is stored per session as JSON on local disk — single-operator, local tool by design; not a multi-user server. Do not expose it to the public internet without authentication.
- Scanned/image PDFs yield no text (text extraction uses `pdftotext`).
- Uploads limited to 25 MB and the extensions listed in `config.py`.
- Documents are structured from your CSVs; factual product/tariff/regulatory content must be supplied and verified by you. Values that cannot be derived are shown as review placeholders, never invented.
