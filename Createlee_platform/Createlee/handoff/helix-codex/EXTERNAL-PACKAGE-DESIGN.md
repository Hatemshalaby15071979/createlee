# Helix-Codex external pack — superseded design note

**Status:** SUPERSEDED 2026-11-09. The design in the first version of this file
described the gate documents with fields (`status`, `demand`,
`generated_at_iso8601`, `signature_instruction`, per-gate payload schemas) that
Helix-Prime's consumer does **not** read. Verified against the real contract
(`release/production_evidence.py::validate_claims`): those templates are refused
**9 of 9**. Keeping the old text would invite someone to hand-build that shape
again, so it is replaced by this note.

## The authoritative design

- **Authoritative client pack:** `../helix-codex-production-pack/` — generated by
  `../helix-codex-build-pack.py`, which delegates to Helix-Prime's own producer
  (`scripts/produce_production_evidence.py`) and re-checks every document with
  the same `validate_claims` the gate uses.
- **Contract (read this, not any restatement):**
  `release/production_evidence.py` in Helix-Prime. Seven top-level fields —
  `gate`, `evidence_type`, `scope`, `issuer`, `issued_at`, `expires_at`,
  `payload` — plus a detached RSA PKCS#1 v1.5 / SHA-256 `.sig` over the exact
  bytes, verified against `HELIX_PRODUCTION_EVIDENCE_PUBKEY`, both declared via
  environment, both outside the repository.
- **Client instructions:** `../helix-codex-production-pack/00-READ-THIS-FIRST.md`
  and `02-STEP-BY-STEP-REPLACEMENT-GUIDE.md`.
- **Operator runbook:** `../helix-codex-production-pack/05-OPERATOR-RETURN-RUNBOOK.md`.

## Why the old handoff templates in this folder still exist

`gate-evidence/` in THIS folder still holds the old-shape templates emitted by
`handoff.py`. They are kept as the recorded failure, not as a usable pack. Do
not send them. If `handoff.py` is later fixed to emit the contract shape, delete
this note and the old templates together.
